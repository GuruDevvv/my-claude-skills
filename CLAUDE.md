# my-claude-skills

## О проекте
Коллекция скиллов для Claude Code. Публикуется на GitHub (GuruDevvv/my-claude-skills), репозиторий **публичный**.

## Структура — две зоны, граница важна

**`mine/` — мои скиллы.** Каждый — папка с `SKILL.md` + `README.md`:
- `spec-first/` — запуск проекта (Vision → Blueprint)
- `product-check/` — проверка идеи до стройки (5 вопросов JTBD + оценка готовности)
- `deep-research/` — структурированное исследование с рейтингами уверенности
- `design-first/` — 4-6 HTML-прототипов дизайна
- `multi-layer-review/` — мульти-ревью спеки параллельными агентами
- `project-audit/` — аудит организации проекта
- `human-text/` — живой русский текст без следов ИИ

В корне остаются только `README.md`, `CLAUDE.md`, `.gitignore`.
Скилл в корне — ошибка: ему место в `mine/` или `external/`.
`HANDOFF.md` живёт локально и в `.gitignore` — репозиторий публичный, рабочим заметкам там не место.

**`external/` — НЕ мои.** Сторонние скиллы под MIT, с атрибуцией и лицензиями авторов.
Правила этой папки:
- каждый скилл — с автором, ссылкой на источник и лицензией в `external/README.md`;
- тексты лицензий лежат в `external/licenses/`, не удалять;
- **добавляешь новый — сначала проверь лицензию** (`gh api repos/<owner>/<repo>` → поле `license`).
  Нет лицензии = все права защищены = класть сюда нельзя. Так отсеян `remotion-best-practices`
  (repo `remotion-dev/skills` без лицензии) — он живёт только локально;
- если правил чужой скилл под Windows — написать об этом в его `README.md` явно, чтобы человек
  понимал, что берёт форк. Сейчас так помечены `doc-to-markdown` и `mermaid-tools`.

## Исследования — внутри скиллов, отдельной папки нет
- `mine/spec-first/research.md` — полное исследование Spec-First методологии (10 методологий,
  12 шаблонов, 6 реальных катастроф → VIBE SPEC)
- `mine/design-first/research.md` — почему прототипы выходили технически безупречными и эмоционально
  никакими; обоснование art-direction слоя

Правило: обоснование скилла кладём **в его же папку** файлом `research.md`. Общую свалку `research/`
разобрали 27.07.2026 — там же лежали устаревший промпт аудита (его заменил сам скилл `project-audit`)
и выполненный план редизайна design-first v3; оба удалены, история git их помнит.

## Установка скилла
Скопировать папку в `~/.claude/skills/<skill-name>/` и перезапустить Claude Code.

## Источник правды
Рабочие копии живут в `~/.claude/skills/`, там же и правятся. Репозиторий отстаёт — перед публикацией
сверять (`diff -rq`), а не заливать вслепую. Мусор (`*.backup*`, `*.orig`, `__pycache__`) не коммитить.

## Публичность — помнить при каждом коммите
Репозиторий открыт всем. Ничего личного, никаких ключей, никаких путей с именами клиентов.
Перед пушем — прогон на секреты.

## Разработка
Для создания и правки скиллов — `skill-conductor` (лежит в `external/skill-conductor/`, ставится как
обычный скилл). Им же прогонять чужой скилл в режиме REVIEW перед тем, как класть его в `external/` —
это дешевле, чем потом обнаружить, что скилл сломан в своей главной функции.
